# v2.0 设计文档 —— AI 老师:错因诊断 + 变式闯关 + 智能错题本 + 访问门 + 服务端同步

> 2026-10-14。目标:一道题做错 → DeepSeek 给出解题思路和线段图 → 立刻生成一道变式题 → 变式再错就再生成,直到做对;
> 错题本升级为"会分析的错题本";套路总结由 AI 结合孩子自己的错题来写。
> 约束:AI 不能被外人白白消耗 Token(验证方式同 mini2.kailorik.com:Cloudflare Access);多设备数据要能稳定同步。

## 0. 现状分析(v1.5)

| 维度 | 现状 | 缺口 |
|---|---|---|
| 讲解 | 生成题/真题都有固定分步讲解 | 不针对孩子"错在哪";看完标准讲解仍不知道自己的卡点 |
| 变式 | 23 个生成器可出同类题;错题本复习按 1/3/7/14 天出一道 | 错了当场没有"再来一道"闭环;basic/geometry(无生成器)只能重做原题;变式和原题结构差异大,不聚焦错因 |
| 画图 | 无;13 道依赖原书配图的题只能标 🖼 | 线段图是小学应用题最核心的工具,却完全缺席 |
| 错题本 | 只记"错了几次、在第几关" | 不知道错因类型,没有学情画像,无法指导下一步 |
| 套路总结 | methods.json 固定词条 | 与孩子自己的错误无关 |
| 同步 | GitHub Gist(每台设备贴 PAT) | ①推送前不拉取 → 两台设备交替时会覆盖对方新数据;②GET gist 响应带 `max-age=60`,浏览器缓存导致拉到旧数据;③删除不传播(删掉的错题会被另一台设备"复活");④同一台设备多标签页互相覆盖 |
| 访问控制 | 公开 GitHub Pages | 加 AI 后必须有门,否则任何人都能刷我们的 DeepSeek 额度 |

## 1. 部署与鉴权(为什么不用"浏览器里填 Key")

DeepSeek API 支持浏览器 CORS,但把 Key 放进前端(哪怕存在 Gist 里再取)都等于把 Key 发给每台设备。按 mini2 的做法:

```
浏览器 ──► Cloudflare Access(邮箱验证码登录,同 mini2 的策略)
            │  通过后请求头带 Cf-Access-Jwt-Assertion
            ▼
       Worker(word-problem-coach)
         ├─ 静态资源(整个站点,Workers Static Assets)
         ├─ /api/me     返回登录邮箱、AI 是否可用、今日额度
         ├─ /api/ai     DeepSeek 代理:Key 只在服务端 secret;模型白名单、max_tokens 上限、每日次数上限
         └─ /api/sync   服务端合并同步(Durable Object,见 §5)
```

- **双重保险**:Access 在边缘拦截;Worker 内再用 Access 公钥(`/cdn-cgi/access/certs`)校验 JWT 的签名、`aud`、`exp`、`iss`,可选邮箱白名单。没配置 `ACCESS_AUD` 时 **默认拒绝**(fail closed)——即使 `*.workers.dev` 地址没挂 Access,也调不动 AI。
- **防浪费**:每日调用上限(默认 300 次,`AI_DAILY_LIMIT` 可调)记在 Durable Object;单次 `max_tokens ≤ 2500`、消息总长 ≤ 24k 字符;前端对讲解结果做本地缓存,同一道错题不重复调用。
- **降级**:GitHub Pages 镜像没有 `/api`,AI 功能自动隐藏,退回"规则诊断 + 本地生成器变式",功能不坏。

## 2. AI 老师:错因诊断 + 解题思路 + 画图

**触发**:刷题机答错(两次机会用完 / 点"不会")、题库自评"做错了"、错题本点"🤖 AI 讲解"。

**两层诊断**:
1. **规则诊断**(离线、即时,`js/diagnose.js`):用孩子的错答和标准讲解里的中间数比对——等于中间步骤结果 → 🪜只做了一半;等于题干里的数 → 👀审题不清;与正确答案相差很小/差 10 倍/数字颠倒 → 🧮计算失误;正确答案 ± 某个已知量 → ❓答非所问;点"不会" → 🤔不会下手;其余 → 🔗数量关系错。
2. **AI 诊断**(DeepSeek,`js/ai/tutor.js`):输入题干、标准讲解、孩子的两次作答、规则诊断、所属套路口诀;输出 JSON:错因类型 + 一句话诊断 + 3~5 步儿童化解题思路 + 套路一句话 + **图**。

**画图**:LLM 不直接自由画,而是输出一个小 DSL,前端用自己的渲染器画成 SVG(`js/diagram.js`),稳定、风格统一、可打印:
- `bars` 线段图/条形模型:每条线段由若干"份"组成(普通/多出来的部分/未知 ? 部分),右侧大括号标总量;
- `line` 数轴/路程图:点标记 + 区间跨度(行程、植树、周期);
- `svg` 仅几何题允许,前端白名单清洗(去 script/事件/外链)后再显示。

## 3. 变式闯关(错 → 变式 → 再错 → 再变式 …… 直到做对)

```
原题 ❌ ─► [AI 诊断 + 思路 + 图] ─► 🔁 变式 1 ─❌─► [诊断] ─► 🔁 变式 2(降一档:数更小、少一步)─✅─► 🎉 闯关成功
```

- **AI 出变式**:保持原题的数量结构和套路,换情境和数字;针对诊断出的错因设计"必须走对的那一步";第 2 关起自动降难度。
- **三道验算闸**,防止 AI 出错题:①返回的 `expression` 用自写的安全四则求值器(`js/ai/expr.js`)算一遍,必须等于 `answer`;②答案必须为正数、最多两位小数;③**独立解题**:把变式题干单独发给 DeepSeek(温度 0,只给题不给答案)解一遍,答案一致才放行。不一致自动重出(最多 3 次),仍失败就退回本地生成器出同类题(23 个模型有生成器,答案构造式保证正确)。
- **记录**:变式题存进 `aiQ`(可复现、可打印、可同步);每次闯关记入错题的 `chain`(原题 → 变式 1 ❌ → 变式 2 ✅);当场闯关不改变 1/3/7/14 天的间隔节奏(当场做对 ≠ 记住了),到期复习仍照常。
- basic / geometry 两类以前"只能重做原题",现在也有 AI 变式了。

## 4. 智能错题本 + 套路总结

- **错因画像**:按 7 类错因统计条形图;按套路统计错题最多的模型;"顽固错题"(错 ≥3 次或变式连错 ≥2)。
- **筛选**:按错因 / 按套路。每道错题显示错因徽章、一句诊断、闯关链。
- **🤖 AI 学情分析**:把错因统计 + 最近错题(题干摘要 + 诊断)发给 DeepSeek,生成"主要问题 / 证据 / 建议 / 本周练习计划 / 鼓励语",存档可回看(按学生)。
- **🧭 我的套路卡**(模型学堂):固定词条(口诀/信号/坑)+ 孩子在这个模型上的错因统计,本地即可显示;AI 版结合孩子的真实错题写"我的易错点 + 解题三步 + 检查清单"。

## 5. 多设备同步(研究结论与方案)

**问题清单**(见 §0)的根因:Gist 不支持条件写(无 compare-and-swap),客户端"读-改-写"之间有竞态;且每台设备要单独贴 PAT。

**方案**:服务端合并。
- 数据仍是一个 JSON 文档;合并规则抽成纯函数 `js/merge.js`,**前后端共用同一份代码**。
- `PUT /api/sync`:客户端把整份本地状态发上去 → Durable Object(单实例、单线程、SQLite 持久化,天然串行)读出云端文档 → `merge(云端, 客户端)` → 写回 → 返回合并结果 → 客户端再合并进本地。因为合并是**并集式、幂等、可交换**的(attempts 按 ts+qid 去重、错题本新者胜、计数取大、卷子逐题并集、AI 题按 id 并集),任意顺序、任意次数同步都收敛到同一结果,不会丢数据。
- **删除传播**:新增 `removed` 墓碑(qid → 删除时间),删除时间晚于错题 lastTs 的条目在合并时剔除。
- **多标签页**:监听 `storage` 事件,把其他标签页写入的状态并入内存。
- **触发**:打开页面、切回页面、联网、每次保存后 2.5 秒防抖。登录 Access 后**零配置自动同步**,不用再贴 PAT。
- Gist 同步保留为后备(GitHub Pages 镜像上用),并修复 `no-store` 缓存问题、改为"先拉再推"。

## 6. 数据结构变更(向后兼容)

```
profile.errorBook[qid] += { diag: {type, note, source, ts}, chain: [{qid, correct, ts, by}] }
profile.attempts[]     += { ans }           // 孩子的作答(诊断用)
profile.aiQ            = { [id]: question } // AI 变式题,封顶 200
profile.aiNotes        = { report: {ts, data}, tricks: { [tag]: {ts, data} } }
profile.removed        = { [qid]: ts }      // 删除墓碑
```
